## Goal
Build a full multi-vertical Retail/Wholesale/Manufacturing ERP system (NexusCore) with 7 Business Profiles, RBAC (4 precise roles), dynamic feature toggles, collapsible sidebar, e-commerce order entry, returns/exchanges hub, premium onboarding gateway, industry theme presets, database-ready schemas, Excel bulk product import, barcode-scan POS speed lane, and RTL-safe Switch.

## Constraints & Preferences
- RTL layout, Arabic text, glassmorphism + Deep Navy/Cyan design tokens (Tailwind v4 with CSS variables for dark/light)
- Central Zustand stores (5) with `persist` middleware for cross-tab state sync
- No PostCSS or Tailwind config files – Tailwind v4 managed via `@tailwindcss/vite` plugin
- All UI components use existing `@/components/ui/*` shadcn-style primitives
- TypeScript strict, Vite 7.3.5, React 19, `crypto.randomUUID()` for ID generation
- Build: `npm run dev` (port 8080), package manager: npm
- Business-specific route placeholders for 8 new profile modules
- 3 governorate shipping tiers (50/65/85 EGP) with 26 governorates
- Deposit toggle for COD in e-commerce orders (no mandatory flag – always rendered when COD)
- Staff roles see only simplified "التفضيلات الشخصية والمظهر" with dark/light toggle, no preset selection
- Frontend TypeScript interfaces use snake_case to match backend DB column names
- Excel bulk import: `xlsx` library, client-side parsing, `NX-XXXXXX` auto-barcode for missing SKU
- Switch component: `w-12 h-6 p-0.5` track, `w-5 h-5` thumb, `rtl:data-[state=checked]:-translate-x-5` for RTL containment
- POS barcode scanner: auto-focus on mount, Enter key matches by `sku` or `barcode`, adds +1 to cart instantly, clears input
- `React.lazy()` requires default export – fixed with `.then()` wrapper or plain import

## Key Decisions
- React Router DOM architecture (not TanStack Router) – layout-Sidebar with `<Outlet />` pattern in `Layout.tsx`
- Five Zustand stores: `useBusinessStore` (business-storage), `useFinancialStore` (financial-storage), `useAuthStore` (auth-storage), `useThemeStore` (theme-storage), `useFeatureStore` (feature-storage)
- `activeBusinessProfile` in auth store replaces `businessType` as primary routing filter
- Collapsible sidebar uses `w-[260px]`/`w-[70px]` pixel values with CSS transitions; main content uses `flex-1 min-w-0 w-full` (no margin-based shifting)
- POS uses `React.lazy()` with default export + ErrorBoundary + auto-fallback products when store is empty
- E-commerce orders at dedicated `/ecommerce-orders` route (not inside POS); Returns hub at `/returns` – both gated by `BusinessProfile` + `RoleGuard` + feature toggles
- Non-owner roles redirected to locked-down settings view ("التفضيلات الشخصية والمظهر") with only dark/light toggle; owner sees full system configuration
- Theme switcher uses `simplified` prop approach to conditionally hide preset/custom sections for non-owner roles
- Frontend TypeScript interfaces adopt snake_case to map directly to DB column names for future ORM integration
- `server/db/schema.sql` created as standalone SQL file (not integrated into build pipeline) for manual migration to Supabase
- Excel import uses `xlsx` for client-side parsing (no server upload); barcode auto-generation uses `NX-XXX…` prefix
- Switch component uses `rtl:` variant for RTL-aware thumb translation instead of relying on natural flow
- POS barcode scanner replaces deposit/shipping sections for clean in-store retail flow – shipping/deposit moved exclusively to e-commerce orders
- E-commerce shipping fees sourced from `useFinancialStore.shippingTariffs` (live, editable via Settings → `ShippingTariffManager`) – single source of truth, no duplication
- Double-entry stock deduction: `addManualOrder` mutates `manualOrders[]` AND `products[]` stock_qty atomically in one `set()` call – `addManualOrder` is the only e-commerce write path, ensuring POS and Inventory reflect changes immediately
- `sanitizeProduct()` helper duplicated in both `pos.tsx` and `ecommerce-orders.tsx` (not shared) to avoid cross-module coupling; both use the same `FALLBACK_PRODUCTS` structure
